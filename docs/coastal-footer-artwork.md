## Analysis and implementation

The desktop drawing reserves a quiet dark upper field for functional text; the three arched bays and water establish the focal point below. The coastline gives depth without card chrome. White live type has a clear role hierarchy: display500 invitation, Manrope400 navigation/locations/utility, display700 natural-proportion wordmark. Small yellow lights echo Blitz's existing accent. The first generated comp's heavier heading rendering is not adopted; actual type follows the homepage500 role.

Paper desktop/mobile boards use the exact production scenes. Display-font proofs use vectors from the real local website font because Paper cannot resolve that family; site text remains normal HTML. Review corrected dark inherited nav headings, moved office email away from bright window linework, tightened links to44px pitch and placed utility text on a solid navy strip. Mobile-v2 was generated as a fresh composition rather than cropping the first design.

`build-footer.mjs` derives native-width and smaller90-quality WebP variants (no enlargement), uses a mobile picture source, fixed intrinsic dimensions, native lazy loading and async decoding. Actual bytes approximately125/320KB desktop and126/387KB mobile; the footer image loads near its section, not at the homepage's first screen. Masters/comp stay outside dist. Every generated page reuses the same footer.

Motion: existing2s linear word reveal triggered by the wordmark entering view (threshold.2), subtle mouse-only6×4px scene parallax, restrained12s reflection pass and42 small engraved-water glints, with32ms frame pacing/DPR1.5. Stops offscreen/hidden/reduced-motion. Mobile disables the canvas loop/allocation; reduced motion shows the wordmark immediately. No pause UI or video is added.
